### 1. 概念层 (Conceptual Level)

**对应内容：全局逻辑蓝图（全公司的统一视图）**

概念层是整个数据库及其全部信息内容的逻辑表示，它不涉及具体的存储细节（如字节或指针），也不涉及特定用户的个性化视图，而是所有用户视图的集合。

**设计实例：**
在我们的“订单数据库”中，概念层由以下**概念模式 (Conceptual Schema)** 定义，包含所有核心数据表及其关系：
*   **Customer 表：** 包含 `Cno` (客户号), `Company` (公司名), `City` (城市), `Tel` (电话)。
*   **Order 表：** 包含 `Ono` (订单号), `Odate` (日期), `Freight` (运费)。
*   **Order_item 表：** 包含 `Ono` (订单号), `Pno` (产品号), `Quantity` (数量)。
*   **Product 表：** 包含 `Pno` (产品号), `Pname` (产品名), `Price` (价格)。

此外，概念层还定义了约束条件，例如：`Price` 必须大于 0，或者 `Order` 表中的 `Cno` 必须存在于 `Customer` 表中（完整性约束）。

---
### 2. 外部层 (External Level) / 用户逻辑层

**对应内容：特定用户的“窗口”（个性化视图）**

这一层是单个用户（应用程序员或终端用户）所看到的数据视图。不同的用户根据权限和需求，只能看到概念层中的一部分数据，或者看到经过处理的数据。

**设计实例：**
在这个系统中，可能有两类不同的用户，他们看到的“外部视图”是完全不同的：

*   **用户 A（销售经理）：**
    *   他只关心销售业绩，不关心客户的具体地址。
    *   **他的视图：** 系统通过 SQL 查询为他生成一个**视图 (View)**，名为 `Sales_Report`。这个视图只显示 `Odate` (日期) 和 `Total_Amount` (订单总金额，通过 `Quantity * Price` 计算得出)。他甚至不知道底层有 `Order_item` 这个表的存在。
*   **用户 B（应用程序员 - 负责发货系统）：**
    *   他使用 Java 或 C++ 编写发货程序。
    *   **他的视图：** 他需要在代码中定义与 `Customer` 表对应的**数据结构（Struct 或 Class）**，包含 `Address` 和 `Tel`，以便打印快递单。他不需要看到产品的 `Price`。

**关键点：** 系统通过 **外部/概念映射 (External/Conceptual Mapping)** 将这些个性化视图与概念层的全局表对应起来。

---
### 3. 内部层 (Internal Level) / 物理层
**对应内容：硬盘上的存储方式（底层实现）**

这一层描述数据在物理存储介质上是如何实际存储的。它涉及字节、索引、指针和哈希方案等底层细节。

**设计实例：**
对于上述的 `Customer` 和 `Order` 表，在硬盘上可能是这样存储的：
*   **存储结构：** `Customer` 表的数据在磁盘上可能按 `Cno` 的顺序连续存储（聚簇），或者存储在特定的哈希桶中以便快速定位。
*   **索引 (Indexes)：** 数据库管理员 (DBA) 决定为 `Order` 表的 `Odate` 字段建立一个 **B+树索引**，以加快按日期查询的速度。
*   **指针：** 系统内部可能使用指针将 `Order` 记录与其对应的 `Order_item` 记录物理连接起来，以提高连接查询的效率。

**关键点：** 系统通过 **概念/内部映射 (Conceptual/Internal Mapping)** 来定义逻辑表（如 `Customer` 表）如何映射到物理文件和块上。

### 总结与映射关系图解

| 架构层级 | 核心定义 | 订单数据库中的具体对应 (实例) |
| :--- | :--- | :--- |
| **外部层** (External) | **用户看到的视图** | **销售经理看到的报表**：只包含“日期”和“销售总额”；<br>**发货员看到的界面**：只包含“客户地址”和“电话”。 |
| **映射 1** | *外部/概念映射* | 定义如何从基础表中计算出“销售总额”，或如何筛选出“客户地址”。(实现逻辑数据独立性) |
| **概念层** (Conceptual) | **全局逻辑结构** | **完整的数据库表定义**：`Customer`, `Order`, `Product` 等所有表及其字段定义、主键外键约束。这是企业的真实数据全貌。 |
| **映射 2** | *概念/内部映射* | 定义 `Customer` 表存储在哪个磁盘分区，以及字段是如何编码的（如 ASCII 或 Unicode）。(实现物理数据独立性) |
| **内部层** (Internal) | **物理存储方式** | **硬盘上的文件**：数据存储在 `D:\Data\order.dat` 文件中；`Cno` 字段上有**索引**；记录之间通过**指针**连接。 |
